# Predictive Autoscaler для микросервисов в Kubernetes

## Описание приложения

Predictive Autoscaler - это система автоматического масштабирования микросервисов в Kubernetes, которая использует прогнозирование временных рядов для заранее (до того, как нагрузка реально вырастет) выставления нужного количества реплик сервисов.

### Основная цель
Предотвращение деградации SLA (уровня сервиса) за счёт более раннего реагирования на изменение нагрузки по сравнению с традиционными методами масштабирования, такими как HPA (Horizontal Pod Autoscaler).

## Архитектура

Приложение состоит из следующих модулей:

1. **config.py** - Загрузка и валидация конфигурационного файла
2. **metrics_collector.py** - Запросы к Prometheus HTTP API для получения метрик нагрузки
3. **forecaster.py** - Алгоритм прогноза с использованием метода Хольта с асимметричной коррекцией риска (ARAF)
4. **decision.py** - Принятие решений по масштабированию с учётом ограничений и cooldown
5. **k8s_client.py** - Взаимодействие с Kubernetes API для чтения/изменения количества реплик
6. **main.py** - Оркестрация процессов: по потоку на сервис, цикл опроса

## Алгоритм работы

1. Сбор метрик нагрузки из Prometheus через API /api/v1/query_range
2. Построение прогноза нагрузки с использованием адаптивного алгоритма ARAF (Asymmetric Risk-Adaptive Forecasting)
3. Принятие решения о количестве реплик с учётом ограничений и cooldown
4. Применение изменений через Kubernetes API

## Особенности алгоритма ARAF

Алгоритм использует адаптивное экспоненциальное сглаживание уровня и тренда (метод Хольта) с асимметричной коррекцией риска недомасштабирования:

- Обычные модели прогноза минимизируют симметричную ошибку
- Для автоскейлинга недооценка нагрузки (простой/деградация SLA) обходится значительно дороже, чем переоценка (немного лишних подов)
- Алгоритм вводит асимметричную коррекцию риска с двумя разными коэффициентами сглаживания в зависимости от знака ошибки:
  - lambda_plus: скорость роста риск-margin при недооценке нагрузки
  - lambda_minus: скорость затухания риск-margin при переоценке (значительно меньше lambda_plus)
- Вес риск-поправки kappa обоснован соотношением стоимости недомасштабирования и стоимости избыточной реплики

## Конфигурация

Файл конфигурации (config.yaml) содержит:
- Адрес Prometheus
- Список сервисов с PromQL-запросом метрики нагрузки
- Параметры масштабирования (min_replicas, max_replicas)
- Параметры алгоритма ARAF (alpha, beta, lambda_plus, lambda_minus, kappa)

## Запуск

### Локальный запуск:
```bash
python -m autoscaler.main --config config.yaml --dry-run -v
```

### Запуск в кластере:
```bash
docker build -t predictive-autoscaler:latest .
kubectl apply -f k8s/rbac.yaml
kubectl apply -f k8s/deployment.yaml
```

Флаг --dry-run позволяет тестировать работу без реальных изменений в кластере.

## Преимущества

1. **Раннее масштабирование** - система реагирует на изменение нагрузки заранее, до того как она достигнет критического уровня
2. **Адаптивность** - использует алгоритм, который учитывает асимметричные последствия ошибок прогноза
3. **Контроль над изменениями** - ограничения на резкое изменение количества реплик и cooldown-периоды предотвращают "дребезг"
4. **Гибкость** - можно легко настраивать параметры для разных сервисов
